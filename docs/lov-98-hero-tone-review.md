# LOV-98 Hero 카피 톤 검수

## 검수 대상
- 스펙: `docs/specs/LOV-95-hero-copy-update.md`
- 구현: `apps/web/components/Hero.tsx`

## 결론
- **판정: 수정 필요 (조건부 미승인)**
- 이유: 현재 H1은 문장 톤 자체는 안정적이지만, 스펙의 단일 결정 카피와 불일치하며 첫 화면에서 "무엇을 하는 회사인지"를 즉시 전달하는 밀도가 상대적으로 낮다.

## 렌즈별 검수
- **Jobs-to-Be-Done**: "바로 실행 가능한 IT 파트너를 찾는다"는 사용자 과업 관점에서, 현재 문구("더 단단한 기술로...")는 결과 약속 중심이라 서비스 정체성 인지가 한 박자 늦다.
- **Value proposition canvas**: pain(실행 불확실성) -> gain(지속 성과) 연결은 있으나, product fit(IT 솔루션 파트너)이 H1에서 직접 드러나지 않는다.
- **One-message-per-asset**: Hero 1차 메시지는 "우리가 무엇을 제공하는가"여야 하는데, 현재는 "어떤 결과를 지향하는가"가 전면이다.
- **Honest claims**: 과장/허위는 없고 현실적 톤은 유지됨.
- **Brand voice consistency**: 신뢰·전문성 톤은 유지되나, 스펙에서 합의된 표현 체계와 어긋남.

## 권고 카피 (단일안)
- H1 line 1: `비즈니스 성장을 위한`
- H1 line 2: `IT 솔루션 파트너`

## 수정 포인트
- Hero 배지(`IT 솔루션 파트너`)와 H1 2행이 중복되므로, 아래 중 하나를 권고:
- 옵션 A(권고): 배지는 현재 유지, H1은 스펙 단일안 그대로 반영(일정 최소화).
- 옵션 B: H1 스펙 반영 + 배지를 "실행 중심 파트너"로 변경(추가 합의 필요).

## 완료 기준
- `apps/web/components/Hero.tsx`의 H1이 스펙 단일안 2줄과 정확히 일치.
- 모바일/태블릿/데스크톱에서 과도한 줄바꿈 없이 가독성 유지.
- 기존 CTA 링크(`href="#contact"`, `href="#about"`) 유지.
